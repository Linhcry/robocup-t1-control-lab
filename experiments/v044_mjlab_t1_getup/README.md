`quality_passed=false`。官方训练后端已经在独立环境中跑通 1、2、16、256、512、1024、2048 和 4096 个并行机器人，4096 环境的正式 3000 轮训练已完整结束：共 294,912,000 个环境步、61 个不可覆盖检查点，证据见 `metrics/v044_training_summary_final_run_01.json`。最后 50 轮训练域内部 `getup_success` 均值为 0.8700，但该指标不检查比赛模型、安全接触或恢复后行走，因此不能直接晋级。

全部 61 个检查点随后在 44700、44701、44702 三组独立随机流中比较，每组 256 个全倒地环境、299 个控制步；提前终止的环境直接判为失败，自动 reset 后的第二次尝试不会计入。正式筛选证据见 `metrics/v044_source_candidate_formal_shortlist_run_01.json`。第 800 轮检查点按预先规定的“连续直立 3 秒最差组→三组均值→曾站起最差组→提前终止率”顺序排名第一：三组连续直立率为 0.9531、0.9375、0.9336，提前终止均为 0。它只获准作为 v045 目标域适配的网络初始化，仍不是 RCSS 起身成绩。

第 700 轮的早期迁移审计已经暴露出明确的 sim-to-sim 差异：同一检查点在官方 play 环境的 16 个随机倒地样本中为 16/16 “曾经站起”，但在比赛 RCSS 的俯卧、仰卧、左侧卧、右侧卧中为 0/4。训练继续到第 1300 轮后，以相同四姿态重新测试仍为 0/4，且关节越限率与手/躯干危险接触率均为 100%；证据见 `metrics/v044_model_1300_fixed_validation_run_01.json`。源机器人有 49 个 geom，比赛模型在加入球衣前为 36 个、比赛中为 38 个，关键躯干、头、手臂、小腿和足部碰撞体不同。因此 v044 将保留为官方源域基线，不会直接部署；目标域续训已另建 v045。

本版本使用官方 `Mjlab-Getup-Flat-Booster-T1` 配方：Actor 观测 75 维、Critic 观测 78 维、动作 23 维，Actor/Critic 隐藏层均为 `512→256→128`，PPO 每环境每轮采样 24 步。训练环境的 `getup_success` 只表示一局中曾经达到过直立高度，而且训练 reset 有 40% 概率直接站立，因此不能拿日志里的该数值冒充倒地起身成功率。

## 为什么单独建立 v044

v039 的 23DoF 串行模型与比赛 RCSS T1 的执行器和动力学不一致，三个检查点均为 0/20。v044 改用与比赛机器人相同总质量、相同 23 关节顺序和相同 XML 限位的官方 Booster T1 模型训练；但训练端是 23 个位置执行器，比赛端是每关节 torque/position/velocity 三执行器，所以仍必须经过 RCSS 闭环迁移评测。

## 严格晋级顺序

1. 运行 `scripts/audit_v044_mapping.py`，证明 23 维顺序、限位、质量和比赛执行器三元组映射没有错位。`run_01` 因把规则角度与 XML 两位小数弧度的允许差设为 0.006 rad 而失败；实测最大舍入差为 0.006126 rad，`run_02` 把容差修正为 0.007 rad，同时仍要求训练 XML 与比赛 MJB 的 23 组限位逐值完全相等。
2. 完成官方 3000 轮训练，并保留每 50 轮检查点，不覆盖历史模型；本项已完成。
3. 固定验证集分别评测俯卧、仰卧、左侧卧、右侧卧，每姿态 20 局。
4. 只有固定集全部通过，才打开每姿态 100 局的封存集。
5. 成功必须同时满足：连续站立 3 秒、随后行走 5 秒且至少前进 1 米、零再次摔倒、零关节越限、零非有限动作，并通过头部、手臂、躯干冲击和扭矩饱和门槛。
6. 四姿态总恢复率至少 97%，任一姿态至少 95%，恢复后行走链至少 95%。所有条件都通过后，起身技能才允许接入 3v3/7v7。
